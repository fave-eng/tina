# Supabase: серверные компоненты

В действующем Supabase-проекте Кристины по состоянию на 19.10.2026 были активны
`kristina-oge-alerts`, `kristina-oge-diary-review`, `kristina-oge-diary-reminder`, `oge-email35-review`.

В этом исходном архиве восстановлена функция `kristina-oge-alerts` по текущей логике,
а также подготовлен новый модуль `kristina-oge-reports`. Он **не развёрнут** и не выполняет рассылку.
Нельзя считать «созданный код» равнозначным «работающему в Supabase».

Для отчётов перед первым деплоем необходимо:
1. Проверить код и выполнить `sql/04_report_deliveries_CREATE_ONLY.sql` в SQL Editor.
2. Проверить заполненность Edge Secrets: `OGE_REPORT_CRON_SECRET`, `OGE_TELEGRAM_BOT_TOKEN`,
   `OGE_REPORT_CHAT_ID`, `OGE_REPORT_THREAD_ID`; не хранить их значения в архиве сайта.
3. Развернуть `kristina-oge-reports` вместе с `_shared/reports-core.js` с verify_jwt=false,
   поскольку функция проверяет отдельный секрет заголовка X-Report-Secret.
4. Запустить защищённый dry_run, проверить текст, выполнить тест Telegram с явного согласия.
5. Лишь после успешной проверки настроить два cron расписания (понедельник 10:00 Уфа,
   первое число месяца 10:00 Уфа), опираясь на актуальную документацию pg_cron/pg_net.

Для `kristina-oge-diary-review` и `oge-email35-review` живые функции существуют, но исходных
файлов в присланном `tina.zip` не было. Их исходники не подменялись фиктивными файлами.
Экспортировать текущие версии следует отдельно через Supabase Dashboard/CLI перед повторным деплоем.

**Безопасность:** у двух старых публичных резервных таблиц `progress_legacy_backup`
и `legacy_progress_snapshots` в Supabase отключён RLS. Нельзя исправлять это автоматически:
требуется проверить использование, права и спроектировать политики, иначе можно нарушить доступ.
