# Кристина · Подготовка к ОГЭ по английскому 2027

## Что это

Рабочий статический учебный сайт с русским интерфейсом для самостоятельной подготовки Кристины к ОГЭ по английскому языку. **Целевой дедлайн подготовки — 1 мая 2027 года**; это не утверждённая дата экзамена.

Версия 4.0 — 10 октября 2026. Создана на основе сайта ученика Даниила и ранее подготовленной версии кабинета Кристины. Отдельные конфигурация и идентификаторы прогресса не затрагивают Даниила.

## Возможности сайта

- 29 учебных недель (с 12 октября 2026 по 1 мая 2027), 3 обязательных самостоятельных занятия в неделю, всего 87 последовательных учебных сессий.
- Каждое занятие: объяснение темы, пример, типичная ошибка, тест с выбором ответа и самостоятельное письменное задание. На неделях есть 18 вопросов по грамматике, 23 по словарю/чтению, 17 по повторению/аудированию (58 проверяемых ответов в неделю, без учёта дополнительных упражнений). 3 занятия считаются завершёнными при результате от 70%, заполненном тексте и прохождении в разные дни. Проверка качества текста автоматически НЕ выполняется.
- Свободное повторение, персональный список **«Мои ошибки»** из неверных ответов. После правильного повторного ответа вопрос удаляется из очереди.
- 44 задания стартовой диагностики грамматики/лексики/чтения. Это ориентировочная диагностика, а не сертифицированная оценка CEFR. Для определения навыков говорения, письма и аудирования требуются дополнительные проверки.
- 98 грамматических подтем в каталоге, 33 темы с отдельным объяснением и мини-тестами.
- Тематический словарь: **1 069 учебных записей** в 23 разделах, карточки, поиск, отметки изученных слов. Это не исчерпывающий официальный словарь ФИПИ. Несколько слов/словосочетаний встречаются в разных разделах, так что количество уникальных единиц может быть меньше числа записей.
- 119 неправильных глаголов с формами V1/V2/V3 и тренировками.
- 29 разных авторских текстов для чтения, 29 разных сценариев для аудирования. **Аудио воспроизводится синтезатором речи браузера**, реальные дикторские аудиозаписи и официальные mp3 ФИПИ сюда не встроены. Вопросы и тексты учебные, не копия официальных экзаменационных материалов.
- Письмо (редактор), устная практика (запись через микрофон в поддерживаемом браузере), короткий тренажёр ОГЭ.
- Отчёты: предпросмотр недельного сообщения (по понедельникам за прошедшую неделю) и месячного (1-го числа за предыдущий месяц, сравнение с позапрошлым). Учитываются попытки, учебные дни, освоенные темы, разделы и типы ошибок. Сообщений после отдельного задания не предусмотрено.
- Сохранение прогресса в браузере, экспорт/импорт резервной копии, **опциональная полная синхронизация прогресса и журнала ошибок через Supabase** после настройки. Данные письма при синхронизации кабинета сохраняются в закрытой учётной записи в Supabase (с RLS), **но не попадают в Telegram-отчёты**.

> Тестовая нагрузка ориентировочная: от 45 до 65 минут на занятие с учётом изучения теории и самостоятельного письма. Фактическая длительность зависит от знаний и темпа Кристины. В поздних неделях банк грамматических вопросов частично повторяется для закрепления; это пока не 87 полностью уникальных экзаменационных вариантов.

## Как посмотреть сайт

Откройте `index.html` в браузере. Для стабильной работы записи звука, части браузерных возможностей и сохранения данных лучше разместить сайт на HTTPS или запустить локально:

```bash
cd kristina_oge_2027_release
python -m http.server 8000
```

Затем откройте `http://localhost:8000` на том же компьютере. Не размещайте `config.js` с секретными ключами; в нём должны быть только публичные параметры Supabase URL и publishable key. Для продакшен-версии — деплой на статический хостинг с HTTPS.

## Как подключить Supabase для сохранения данных между устройствами

Не выбирайте проект Даниила автоматически. Используйте **отдельный проект Кристины** или строго обособленную схему с проверенными политиками. Приведённый SQL создаёт таблицы с префиксом `oge_` и включает RLS. **Сначала проверьте SQL и резервные копии, затем применяйте его только в правильном проекте.**

1. Создайте Supabase-проект и включите нужный способ аутентификации (например, email/password).
2. Выполните `supabase/sql/setup_reports.sql` и `supabase/sql/setup_student_state.sql` в SQL Editor выбранного проекта. Убедитесь, что RLS работает: авторизованный пользователь видит только свои строки, а anon не видит данные.
3. Опубликуйте сайт по HTTPS, в `config.js` укажите `cloud.enabled=true`, `cloud.url='https://...supabase.co'` и публичный `cloud.publishableKey` — никакого `service_role` в браузере. Проверьте Auth URL Configuration для хостинга.
4. В настройках сайта Кристина создаёт свою учётную запись и входит. Если включено подтверждение почты, сначала подтверждает адрес. После входа приложение объединяет локальное и облачное состояние, загружает прогресс в `oge_student_state`, а события ошибок в `oge_report_events`.
5. Проверяйте вход и продолжение занятий на втором устройстве перед реальной подготовкой. Объединение данных оптимизировано для личного использования одним учеником; одновременное редактирование на двух устройствах **не реализует распределённую транзакционную синхронизацию**, поэтому лучше не проходить одно и то же занятие одновременно на двух устройствах.

## Как подключить Telegram — только еженедельный и ежемесячный отчёты

Адрес назначения: https://t.me/c/4401673540/3. Идентификаторы `REPORT_CHAT_ID` и `REPORT_THREAD_ID` надо **подтвердить через Bot API** или обновление от бота; одна лишь ссылка не является надёжным подтверждением ID темы. Бот должен иметь доступ к чату и право публиковать сообщения.

1. Разверните `supabase/functions/kristina-oge-reports/index.ts` с `supabase/functions/_shared/reports-core.js`. В `supabase/config.toml` стоит `verify_jwt=false`, поэтому критически важно задать `REPORT_CRON_SECRET` и убедиться, что функция отвергает любые POST без верного заголовка `X-Report-Secret`.
2. В Supabase Function Secrets добавьте **только на сервере**: `TELEGRAM_BOT_TOKEN`, `REPORT_CHAT_ID`, `REPORT_THREAD_ID`, `REPORT_USER_ID` (UUID Кристины из Supabase Auth), `REPORT_CRON_SECRET`. `SUPABASE_URL` и `SUPABASE_SERVICE_ROLE_KEY` должны оставаться только на стороне серверной функции. Не отправляйте никакие токены в чат и не помещайте в ZIP/репозиторий.
3. Настройте `pg_cron` + `pg_net` и Supabase Vault; адаптируйте `supabase/sql/setup_cron.sql.template` к фактическому проекту и тому же `REPORT_CRON_SECRET`. Расписание в шаблоне: **понедельник 10:00 по Уфе**, **1-го числа в 10:05 по Уфе**. Уфа — UTC+05:00.
4. Проверьте режим `dry_run` в надлежащий день и один контролируемый реальный Telegram-отчёт. Проверяйте Function Logs, Cron Logs и Telegram. Сервер хранит claim на период, чтобы автоматическая повторная отправка не создавала дублей; если отправка была неопределённой, требуются ручная проверка логов и решение о повторе.
5. Сообщения о **каждом выполненном упражнении НЕ отправляются**. В отчёте используются агрегаты по темам, ошибкам, занятиям и датам. Готовые тексты и записи голоса туда не отправляются.

Документация Supabase: https://supabase.com/docs/guides/functions/schedule-functions и https://supabase.com/docs/guides/functions/auth .

## Официальные материалы ОГЭ-2027

Страница ФИПИ с **проектами** демонстрационных материалов и кодификатором: https://fipi.ru/oge/demoversii-specifikacii-kodifikatory . Сайт предлагает ссылки на официальный банк и навигатор ФИПИ. Составленных для платформы тренировочных заданий недостаточно, чтобы гарантировать результат экзамена; письмо и говорение нужно регулярно проверять по действующим критериям ФИПИ. При публикации окончательной документации ОГЭ-2027 проверьте изменения.

## Тестирование текущей версии

В локальном браузерном прогоне проверены: запуск, основные разделы, 3 полноценных занятия в три отдельные даты, 70-процентный порог зачёта, сохранение на этом устройстве, добавление и разбор ошибки, формирование недельного отчёта, форматирование на 390 px и отсутствие ошибок JS в проверенных сценариях. Через JavaScript дополнительно проверено соответствие ответов вариантам для всех 29 недель (1 682 появления тестовых вопросов) и уникальность всех 29 текстов для чтения и всех 29 аудиосценариев.

**Не проверены на настоящем сервере:** работа Supabase Auth/RLS в конкретном проекте, реальная синхронизация на двух устройствах, отправка Telegram-ботом и задачи Cron. До настройки серверной части интерфейс честно показывает отсутствие облачного подключения. Деплой на домен также не выполнен.
