# Дневник Кристины — ОГЭ 2027 · v17

## Что меняется
В сайте появляется раздел «Мой дневник»: свободный английский текст от **двух предложений ежедневно**, автоматическое локальное сохранение черновика, синхронизация черновика и записи с Supabase, история дней, проверка языка с объяснениями на русском. Текст дневника **не отправляется в Telegram**.

## Установка на сайте
1. Войдите в кабинет Кристины и скачайте резервную JSON-копию прогресса.
2. Замените **app.js**, **cloud-sync.js**, **index.html**; добавьте **journal.js** и **study-diary.css**. Другие файлы сайта не трогайте. Не заменяйте **config.js**.
3. Откройте «Мой дневник», убедитесь, что Кристина авторизована, введите два предложения, проверьте статус «сохранено в облаке». Обновите сайт, убедитесь, что запись осталась.

## Supabase — выполнено автоматически
В проекте `zqzgarvmpqqqaobeicpc` создана закрытая таблица `oge_journal_entries`, функция `oge_save_diary`, журнал отправок и ограничений тестов. Функция `kristina-oge-diary-review` уже развёрнута. Не создавайте эти таблицы повторно. RLS разрешает чтение дневника только самой Кристине.

## Чтобы включить автоматическую проверку английского
В Supabase → Edge Functions → Secrets добавьте `OPENAI_API_KEY` — ключ для отдельной серверной AI-проверки. **Не помещайте ключ в GitHub или файлы сайта.** При отсутствии ключа запись сохранится, но проверка честно сообщит, что она не подключена. Проверка сохраняет правильный вариант, список ошибок и пояснения на русском. AI может допускать неточности; для объективной оценки творческих письменных ответов преподаватель всё ещё нужен. После отправки двух предложений сайт автоматически запрашивает AI-проверку; при необходимости её можно повторить кнопкой «Проверить английский». Текст передаётся только серверному AI-сервису, не в Telegram.

## Чтобы включить Telegram в 21:00 по Уфе
1. В Supabase → Edge Functions создайте `kristina-oge-diary-reminder`. Вставьте файл `supabase/functions/kristina-oge-diary-reminder/index.ts`. Настройка Verify JWT = **off**, потому что функция отдельно проверяет пользовательский JWT для теста и заголовок с секретом для Cron.
2. В Supabase → Edge Functions → Secrets добавьте или проверьте следующие серверные переменные:
   - `OGE_TELEGRAM_BOT_TOKEN` (или уже используемый `TELEGRAM_BOT_TOKEN`), токен вашего бота;
   - `OGE_REPORT_CHAT_ID`, реальный Telegram chat.id;
   - `OGE_REPORT_THREAD_ID`, реальный message_thread_id нужной темы;
   - `OGE_REPORT_CRON_SECRET`, длинная секретная строка для запуска расписания.
3. **Пробная отправка обязательна.** Откройте обновлённый сайт под аккаунтом Кристины → «Мой дневник» → «Отправить тестовое уведомление». Дождитесь сообщения с номером `message_id` и проверьте, что оно действительно появилось в нужной теме. Ссылка `https://t.me/c/4401673540/3` сама по себе не доказывает эти идентификаторы. Если сообщение не появилось, не включайте расписание.
4. После успешного теста в Supabase → Database → Extensions включите `pg_cron` и `pg_net`. Создайте в Vault секреты `oge_project_url` (полный проектный URL) и `oge_report_cron_secret` (точно тот же секрет, что в Edge Secrets). Выполните SQL `supabase/sql/01_schedule_2100_ufa_AFTER_TEST.sql` один раз.
5. На следующий день проверьте `supabase/sql/02_verify_delivery.sql` и саму Telegram-тему. Отправка сообщений ежедневная: если дневник заполнен, придёт короткое подтверждение; если нет — напоминание написать два предложения.

**Нельзя считать напоминания подключёнными до успешной пробной отправки и запуска Cron.** Функция отправки предоставляется для ручной установки, так как её автоматическое развёртывание было заблокировано инструментом. Секреты бота здесь отсутствуют.

## Важно
- Время `0 16 * * *` означает **21:00 Уфа**, так как Уфа UTC+5 и не переводит часы.
- Дневник приватный для аккаунта Кристины; данные не включены в публичные отчёты.
- Написание двух предложений не считается автоматически выполнением отдельного обязательного занятия 3 раза в неделю.
- При обновлении не очищайте localStorage и не сбрасывайте прогресс.
