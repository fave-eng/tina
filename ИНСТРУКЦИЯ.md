# Кристина — еженедельные и ежемесячные отчёты в Telegram

Комплект **только для Supabase**, сайт Кристины и данные других учеников не заменять.

**Проект Supabase:** `общий`, ref `zqzgarvmpqqqaobeicpc`.

**Отчёты:** каждый понедельник в 10:00 по Уфе за прошедшую неделю; 1-го числа каждого месяца в 10:05 по Уфе за предыдущий месяц с сравнением с позапрошлым. Отправки после каждого задания нет. Отчёты включают учебные дни, зачтённые занятия, точность, освоенные темы, словарь и разбор ошибок. При недостаточных данных вместо ложной оценки динамики выводится предупреждение.

**Статус сейчас:** файлы подготовлены, но **пока не развёрнуты и не настроены**. Без секретов Telegram и расписания автоматические сообщения не придут.

## 1. Создать служебную таблицу

В панели Supabase выберите проект **общий** → **SQL Editor** → New query. Вставьте содержимое `supabase/sql/01_report_deliveries.sql` и запустите Run.

Этот скрипт только создаёт таблицу `oge_report_deliveries` (с RLS и без доступа из браузера). **Не запускайте** заново старые `setup_reports.sql` или `setup_student_state.sql`: для этой задачи они не нужны, а часть старых инструкций меняет уже существующие права.

## 2. Развернуть Edge Function

Supabase → **Edge Functions** → создать функцию с именем **`kristina-oge-reports`**. В редактор функции вставьте **весь** код из:

`supabase/functions/kristina-oge-reports/index.ts`

Это самодостаточный файл. Настройка **Verify JWT должна быть выключена** (`verify_jwt = false`), поскольку функция запускается планировщиком без пользовательского JWT. Вместо него код обязательно проверяет секретный HTTP-заголовок `X-Report-Secret`. Без правильного секрета функция отвечает `401`.

Если разворачиваете через Supabase CLI, аналогичная настройка находится в `supabase/config.toml`.

## 3. Задать секреты функции

Supabase → **Edge Functions → Secrets**. Добавьте четыре секрета (названия и формат см. `SECRETS.example.txt`):

- `OGE_TELEGRAM_BOT_TOKEN` — токен уже существующего Telegram-бота
- `OGE_REPORT_CHAT_ID` — проверенный числовой `chat.id` супергруппы
- `OGE_REPORT_THREAD_ID` — проверенный числовой `message_thread_id` нужной темы
- `OGE_REPORT_CRON_SECRET` — новая длинная случайная строка, известная только серверу

Не помещайте их в `index.html`, `config.js`, Github или переписку. `SUPABASE_URL` и `SUPABASE_SERVICE_ROLE_KEY` обычно автоматически доступны функциям, развёрнутым в Supabase. Если в панели какой-то из этих секретов недоступен, обратитесь к настройкам проекта, но **не копируйте service role в клиентский сайт**.

**Важно:** ссылка `https://t.me/c/4401673540/3` **не является подтверждением** реального `chat.id` и `message_thread_id`. Эти значения нужно получить из Bot API / уже работающих настроек бота и подтвердить тестовой отправкой. У бота должны быть права отправлять сообщения в нужную группу и тему. Если бот использует webhook, `getUpdates` может быть недоступен; в таком случае смотрите обновления в собственном webhook или логах.

Секрет `OGE_REPORT_STUDENT_USER_ID` **не обязателен**: функция самостоятельно ищет единственную запись с `studentId = kristina-oge-2027`. Если таких аккаунтов окажется несколько, укажите UUID правильной записи в `OGE_REPORT_STUDENT_USER_ID`.

## 4. Сделать тест Telegram и предпросмотр

В разделе **Edge Functions → kristina-oge-reports → Test/Invoke**:

Заголовки запроса:

`Content-Type: application/json`

`X-Report-Secret: ЗНАЧЕНИЕ_OGE_REPORT_CRON_SECRET`

Тело запроса **для одного тестового сообщения**:

```json
{"test_telegram":true}
```

Ожидаемый ответ: `{"test_sent":true,...}` и одна тестовая запись в теме. Если возникает Telegram `chat not found` / `message thread not found`, сначала уточните реальные идентификаторы и права бота.

Тело запроса **для предпросмотра отчёта без отправки в Telegram**:

```json
{"period":"weekly","dry_run":true}
```

или `{"period":"monthly","dry_run":true}`. В результате вернётся `preview` с текстом сообщения и `events_count`.

Если сайт Кристины ещё не синхронизирован в Supabase, функция сообщит об этом; сначала нужно завершить вход и сохранение на сайте.

## 5. Включить расписание

Supabase → **Database → Extensions**: включите `pg_cron` и `pg_net`, если они не включены. Затем откройте **Vault** и создайте два секрета:

| Имя секрета в Vault | Значение |
|---|---|
| `oge_project_url` | `https://zqzgarvmpqqqaobeicpc.supabase.co` |
| `oge_report_cron_secret` | **в точности то же значение**, что `OGE_REPORT_CRON_SECRET` в Secrets функции |

Затем в SQL Editor выполните `supabase/sql/02_schedule.sql`. Он создаст два задания `kristina-oge-weekly` (05:00 UTC каждый понедельник) и `kristina-oge-monthly` (05:05 UTC 1-го числа). Время для Уфы соответственно 10:00 и 10:05.

**Не запускайте 02_schedule.sql, пока не подтверждена тестовая доставка** — иначе планировщик будет регулярно возвращать ошибки.

## 6. Проверить работу и при необходимости остановить

Для чтения состояния используйте `supabase/sql/03_check_status.sql`.

Следующие даты при запуске в октябре 2026 года: **19 октября** — первый полный недельный отчёт, **1 ноября** — первый месячный отчёт (сравнение октября с сентябрём при недостатке данных). Отчёты не отправляются за пределами учебной программы после начала мая 2027 года.

Скрипт защищает от повторной отправки одного отчёта. Если запрос Telegram завершится сетевой ошибкой, запись о попытке останется: её **нельзя автоматически сбрасывать**, пока не проверено, что сообщение не появилось в теме. Это сделано для защиты от дублей.

## Отдельно о надписи «Не подключено» на сайте

Фраза в `config.js` прежней версии сайта статическая. Она **не изменится сама от запуска функции**. Когда реальная отправка подтверждена, понадобится отдельно обновить индикатор статуса на сайте. **Не меняйте его на «Подключено» до теста:** это дало бы ложное подтверждение.

## Безопасность

- Ключ `SUPABASE_SERVICE_ROLE_KEY` и Telegram-токен должны оставаться на сервере.
- В Telegram отправляется только учебная статистика, без текста письменных ответов, аудиозаписей и учётных данных Кристины.
- Новая служебная таблица имеет RLS и не доступна анонимным клиентам.
- Настройка не исправляет автоматически старые таблицы `progress_legacy_backup` и `legacy_progress_snapshots` без RLS в общем проекте. Их защиту следует рассмотреть отдельно, после проверки потребителей этих таблиц.
